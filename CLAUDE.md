# CLAUDE.md

Personal **Python 3.14** reference for DSA and LLD interviews, published as a Docusaurus site to GitHub Pages at `https://anikeshk.com/python-kitchen-sink/`.

## Repo layout

- `python-kitchen-sink/`: the Docusaurus 3 site (the npm project root).
  - `docs/`: all content, one `.mdx` file per topic, grouped into section folders (`basics/`, `data-structures/`, `builtins/`, `collections/`, `heapq/`, `functools/`, `math/`, `oop/`, `advanced/`, `design-patterns/`). `advanced/` also holds the `bisect/` and `itertools/` sub-sections.
  - `docs/index.mdx`: landing page (`slug: /`) with the numbered list of sections. Update it when adding or renaming a section.
  - `docusaurus.config.ts`: docs are served at the site root (`routeBasePath: '/'`), blog disabled, local search via `@easyops-cn/docusaurus-search-local`, `onBrokenLinks: 'throw'`.
  - `sidebars.ts`: sidebar is fully autogenerated from the folder structure. Don't hand-edit it; control order with `_category_.json` and `sidebar_position`.
- `.github/workflows/deploy.yml`: on push to `main`, runs `npm ci && npm run build` in `python-kitchen-sink/` and deploys to Pages. A broken build blocks the deploy.
- `TODO.md`: planned work (DSA templates section under `docs/dsa-templates/`).
- `LEETCODE.md`: notes about the LeetCode runtime that intentionally stay off the website.

## Page format (follow this for every page)

Every page has the same three-part flow: **short description, then sample code and examples, then refs to official docs.**

````mdx
---
title: Counter
sidebar_position: 3
---

One short paragraph: what it is, its complexity, and when to reach for it in an interview
(e.g. "Use it for frequency problems: anagrams, top-k frequent...").

## Syntax

```python
from collections import Counter

c = Counter("banana")  # -> Counter({'a': 3, 'n': 2, 'b': 1}), O(n)
c["z"]                 # -> 0, no KeyError and no insertion
```

### Named example or variant (e.g. "most_common", "Ransom note (LeetCode 383)")

```python
...
```

## Docs

- [collections.Counter](https://docs.python.org/3.14/library/collections.html#collections.Counter)
- [Counter.most_common](https://docs.python.org/3.14/library/collections.html#collections.Counter.most_common)
````

Conventions:

- **Description**: one paragraph, no heading. Practical and interview-oriented: what it does, Big-O, typical use cases, gotchas.
- **`## Syntax`**: the core snippet first, then `###` sub-sections for variants, idioms and worked examples (LeetCode problems referenced by name and number).
- Code blocks are ` ```python `, self-contained and copy-pasteable: each block repeats its own imports.
- Show results inline with `# -> value` comments; add complexity (`O(n)`) and version notes (`(3.10+)`) in comments where useful.
- Use modern Python: built-in generics (`list[int]`), `X | None`, `match`, type hints in LLD/OOP code.
- **`## Docs`**: last section, a bullet list of links to the official docs, always pinned to **3.14** (`https://docs.python.org/3.14/...`) with an anchor to the exact function/class where possible. Link text is the qualified name (`collections.Counter`, `heapq.heappush`).
- Plain Markdown only. No MDX imports, components or tabs are used anywhere.

## Adding content

- New page: create `docs/<section>/<topic>.mdx` (kebab-case filename) with `title` and `sidebar_position` front matter.
- New section: create the folder plus `_category_.json`:
  ```json
  {
    "label": "collections",
    "position": 4,
    "link": {
      "type": "generated-index",
      "slug": "/collections",
      "description": "deque, defaultdict, Counter, OrderedDict, namedtuple."
    }
  }
  ```
  then add it to the numbered list in `docs/index.mdx`.
- Sub-sections nest a folder with its own `_category_.json` inside a section; set its slug to the full path (e.g. `/advanced/bisect`).
- Internal links use the root-relative slug (e.g. `/collections`), since docs live at the site root.

## Commands

Run from `python-kitchen-sink/`:

```bash
npm ci            # install
npm start         # dev server with hot reload
npm run build     # production build; run this before pushing (broken links fail the build)
npm run typecheck # tsc over the config files
```
